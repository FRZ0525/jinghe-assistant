# 晶核助手 · 设备同步版

用于记录《晶核》常规服和赛季服的副本次数和每日体力。首次打开显示常规服。每个账号可管理多个区服及其角色。

## 在自己的服务器上部署

解压后将目录放到已安装 Docker 和 Docker Compose 的服务器。将域名解析到该服务器，并开放 TCP 80 和 443。Caddy 会为该域名申请 HTTPS 证书。

```sh
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，将 `JINGHE_DOMAIN` 改为自己的域名。保存后启动服务，查看首次设置链接。

```sh
docker compose up -d --build
docker compose logs --tail=30 app
```

在浏览器打开日志里的「首次设置同步密码」链接，填写并确认同步密码。之后其他设备通过同一个网址登录。若旧部署已在 `.env` 设置过密码，直接用已有密码登录，可通过「设备同步 → 修改同步密码」管理。

浏览器会保留本机副本，服务器记录保存在 Docker 的 `records` 数据卷内，对应容器里的 `/data/jinghe.sqlite`。请在原部署目录更新并保留数据卷。可以通过「更多 → 数据备份」另存一份 JSON。

### 本机试用

需要 Node.js 24 或更新版本。PowerShell 中启动，然后打开 `http://127.0.0.1:8765`，在「设备同步」设置密码。

```powershell
npm.cmd start
```

此命令默认把本机试用记录保存在项目下的 `data/jinghe.sqlite`。如果 8765 已有服务，可以先设置 `JINGHE_PORT` 为其他端口，再打开对应地址。

## 手机和电脑同步

1. 如果旧网址已有数据，在旧站点打开「更多 → 数据备份」下载 JSON，然后在新站导入一次。
2. 在导入过记录的设备上打开右上角「设备同步」，输入同步密码。服务器还没有记录时，会自动上传本机记录。
3. 手机和电脑打开同一个新网址，各自登录一次。其他空白设备会自动下载已有进度。

常规服、赛季服、账号与区服、角色、团本配置、体力和挑战次数会自动同步。断网时可以在已打开的页面继续记录，重连后自动提交。两台设备改到同一项且结果不同时，打开「设备同步」选择保留哪一端的冲突项。如果首次连接时两端都已有不同记录，可先下载本机备份，再选择以哪一份为准。

两端都有改动时，冲突列表会并排显示本机和服务器的值。可逐项选择，也可统一采用某一端的冲突值。共享团本额度和受其影响的记录作为一组选择。

一个部署实例对应一套个人记录。同一个同步密码可以用于自己的多台设备。游戏账号名称仍在「账号与角色」内管理。

## 日常使用

顶部的「副本次数」和「每日体力」显示当前服的进度，点击可切换对应列表。可按账号、区服、角色或副本名搜索，并按是否待办筛选。各服分别记住列表设置。

顶部显示铠甲兽当日最新有效挂单的比例。常规服为铸纹币，赛季服为金币。两行分别显示一万个币值多少元和一元可购得多少万个币，并列出挂单更新和上次检查时间。页面打开时每小时刷新一次，服务端按服别缓存一小时。

在「设置」中管理副本目录、选择多选或双副本轮换，并调整次数上限。两服分别保存配置。

常规服账号默认共享 180 次团本总奖励额度。账号卡片的「设置额度」可调整总额和每个团本的账号额度，角色副本行的分母可调整该角色的单本额度。标记副本完成会同时扣除相关已配置额度。日切清除今日标记，剩余次数保留到手动恢复或录入新读数。

「恢复副本次数」可以指定账号和团本，先查看会变更的次数，再确认。截图、名单、备份导入和批量恢复会先保存恢复点。通过「更多 → 恢复点」可以在操作过的浏览器回退最近 8 次批量变更。遇到后来又修改的项目时可以选择如何处理。

## 截图批量录入

在「账号与角色」打开「批量录入」。复制截图后按 Ctrl+V 或 ⌘V，也可点「粘贴截图」或「上传截图」。每张图可单独选择类型、账号和区服，默认归属会预填上次成功导入的账号和区服。点「识别截图」，在表格里查看来源、现有值和导入值，可逐条修正或跳过。团本次数导入时选择截图显示的数值是剩余还是已用。重复读数会去重，冲突要先核对。

识别组件按需从本站加载，在浏览器里处理图片。多张图可放进同一草稿。常规服挑战统计的底部「总计」会填入账号额度。同一批账号额度对应一个账号，被遮挡或未截取的次数保留原记录。另支持粘贴名单和次数。
